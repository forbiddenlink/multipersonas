## 🔴 P0 — Release blockers (before the audit path serves the public)

1. **SSRF subresource bypass** — `src/agent/engine.ts:433`. Per-request guard only vets
   `resourceType==='document'`; subresource `fetch`/`img`/`script` pass unchecked → an audited
   (attacker-controlled) page can hit `169.254.169.254`/RFC1918 and exfil via another fetch. Compounds
   SEC-5 (DNS-rebind TOCTOU, `src/security/url-guard.ts:176`) + DEPLOY-1 (no egress isolation, still
   open per `docs/DEPLOYMENT.md`). **Fix:** run `isUrlAllowed`+`isInScope` on ALL resourceTypes, and
   land the worker behind an egress firewall (or Browserbase-over-CDP). CONFIRMED.
2. **Worker job-lifecycle has no failure recovery** — `worker/src/index.ts:170-192` +
   `web/supabase/migrations/…audit_jobs_queue.sql`. Crash/OOM/SIGKILL/hang strands the row in `running`
   forever: no reaper, no visibility-timeout, `attempts` incremented but never read (no dead-letter),
   no SIGTERM trap, no per-run timeout; one hung nav freezes the single-worker queue. **Fix:** reaper
   RPC resetting stale `running`→`queued` past a timeout, max-attempts dead-letter, `Promise.race` run
   timeout, SIGTERM handler. CONFIRMED — live in prod (worker polls 24/7); not yet hit only because
   real traffic is ~0.
3. **Spend reservation never released on failure** — `web/src/app/api/audit/route.ts:99`. `reserveSpend`
   increments before enqueue; worker failure / crash / failed-enqueue never refund → a day of stuck
   jobs fills the daily cap with phantom calls and refuses real audits (self-DoS). **Fix:** release on
   terminal failure + enqueue error, or reserve at claim-time in the worker. CONFIRMED.
4. **Zero error tracking / alerting / health** — no `@sentry/*` (web+worker), no `/api/health`, no
   uptime monitor, no page-on-failure; worker insert failures `console.error`'d and swallowed
   (`worker/src/index.ts:110`). A cold launch would be blind. **Fix:** Sentry (web+worker) + `/api/health`
   (DB+queue reachability) + free-tier uptime + Slack alert on worker crash/stuck-queue.
