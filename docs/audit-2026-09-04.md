## Coordinated rollout required

1. Enter maintenance: pause new scans and scheduled admission; drain old workers and confirm no scan processes remain active.
2. Apply migrations 024–028. Verify grants and RPC behavior with synthetic probes.
3. Deploy the matching web and worker revisions; verify worker image containment and terminal result persistence.
4. Probe a synthetic public grade, authenticated entitlement denial, scheduled spend limits and health status. Confirm alerts reach the operator before resuming admission.

New web code depends on the new grade/scheduler RPCs. Migration 027 disables the old waitlist route's direct client insert before the updated server route is deployed. Maintenance avoids those mixed-release failures. Old workers can still refund started work, so draining them is part of spending protection.

Do not undo entitlement grants or spending protections as a rollback shortcut. Prefer a compatible forward fix or a tested application rollback that preserves the corrected database boundaries. A full recovery/rollback exercise has not been established.
