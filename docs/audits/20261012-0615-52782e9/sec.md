## Verdicts

- Security posture: **Needs work** (no Critical found).
- Isolation enforcement: **Defense-in-depth for reads** (RLS + app ownership checks + SQL tests); **single layer for writes to evidence tables** (SEC-002).
- Cross-tenant leak risk: **None found** in code read. Not tested against a live database.
- IDOR exposure: **Tested clean by code read** on every route handler and server action; no live probe.
- SSRF posture: **Needs work** (app-layer guard has a proven blind spot; network guard is the real control).
- Hosted `--allow-private`: **Cannot be set.** `allowPrivate` has one source, `src/cli.ts` options. Web calls `assertUrlAllowed(url)` with no options (`web/src/app/api/audit/route.ts:67`, `web/src/app/api/grade/route.ts:56`). Worker calls `gradeScan(input.url, { maxPages: 10 })` and `runMultiPersonaTest({ url, personas, task, outputDir, parallel, runAxe })` (`worker/src/scan-process.ts:13,18`), defaulting to `false` (`src/agent/orchestrator.ts:166`). The job row has no such field and no env var reads it (grep for `ALLOW_PRIVATE` returned nothing). Rung 3 (walked path).
- Webhooks: signature verified on the one inbound endpoint; no idempotency table but handler is state-derived (safe); failures are dropped silently (SEC-005).
- Multi-tab auth: **Not tested** (no browser).
- Launch blockers: none Critical. SEC-001 (High) should be decided before wider anonymous traffic to the grader.

### Evidence notes

SEC-003 probes (local, loopback only, Chromium rev 1243 headless shell, Playwright 1.62.1 client; `executablePath` override because the 1234 build is not installed):
- `redirect-probe.mjs`: `ctx.route` handler logged only the first URL; `page.url()` ended on the redirect target; `title` = `SECRET-B`; both servers reported a hit.
- `proxy-bypass-probe.mjs`: with `launch({ proxy })`, requests to `127.0.0.1`, `localhost`, `[::1]`, `169.254.1.1:8080`, `10.255.255.1:8080` all went through the proxy. This refutes my own hypothesis that Chromium's implicit loopback or link-local proxy bypass weakens smokescreen: Playwright adds the `<-loopback>` override. So the network guard does cover redirect hops, which is why SEC-003 is Medium and not High.
